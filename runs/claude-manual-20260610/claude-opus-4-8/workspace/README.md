# Warband

A complete, playable real-time strategy game in the spirit of *Warcraft II*, running
entirely in the browser on a single HTML5 Canvas. Two mirrored factions (Humans and
Orcs), resource gathering, base building, a tech tree, fog of war, A\* pathfinding, a
scripted AI opponent, and a five-level campaign whose maps are generated by a genuine
Wave Function Collapse algorithm.

No game engine, no runtime dependencies — just TypeScript, Canvas 2D, and a fixed-step
simulation. (`package.json` `dependencies` is empty; only dev tooling is used.)

## Running

```bash
npm install        # installs dev tooling only (vite, typescript, vitest, eslint)
npm run dev        # start the dev server, then open the printed URL
```

Other scripts:

```bash
npm run build      # type-check (tsc --noEmit) + production bundle into dist/
npm run preview    # serve the production build
npm run test       # run the unit/integration test suite (vitest)
npm run lint       # eslint
```

### Reproducing a map

Every source of in-game randomness flows through one seeded PRNG (mulberry32, in
`src/core/rng.ts`). The active **campaign seed** is shown in the top resource bar and can
be set from the main menu or via the URL:

```
?seed=12345
```

Each level's map is derived deterministically from `(campaignSeed, levelIndex)`, so a
given seed reproduces all five campaign maps exactly. If no seed is supplied a random one
is chosen and displayed — copy it into `?seed=` to replay the same campaign.

| Box-select | Left-drag |

| Issue context order (move / attack / harvest / repair / set rally) | Right-click |

| Scroll the viewport | Arrow keys / **WASD**, screen-edge mouse, or minimap click-drag |

| Toggle game speed (1× / 2×) | Speed button in the top bar |

Right-click is context-sensitive: on an enemy it attacks, on a gold mine or forest a
Worker harvests, on a damaged friendly building a Worker repairs, on an unfinished
building a Worker resumes construction, otherwise it moves. With only buildings selected,
right-click sets their rally point.

## Gameplay

- **Resources:** gold (from gold-mine tiles), wood (chopping forest tiles, which deplete
  to dirt), and food/supply (from the Town Hall and Farms). Training is blocked at the
  supply cap.
- **Buildings (5, mirrored):** Town Hall (drop-off, trains Workers, +supply), Farm
  (+supply), Barracks (trains military), Lumber Mill (wood drop-off, unlocks the ranged
  unit), Guard Tower (static ranged defence).
- **Units (4, mirrored):** Worker (harvest/build/repair), melee infantry (Footman /
  Grunt), ranged (Archer / Spearthrower, needs a Lumber Mill), heavy melee (Knight /
  Ogre, needs Barracks **and** Lumber Mill).
- **Tech tree:** prerequisites are enforced for both training and construction (see
  `UNIT_REQUIREMENTS` / `BUILDING_REQUIREMENTS` in `src/sim/stats.ts`).
- **Win/lose:** a side loses when all its buildings are destroyed. Victory unlocks and
  advances to the next campaign level (progress is saved in `localStorage`).

All unit/building numbers live in a single data-driven table (`src/sim/stats.ts`).

## Architecture

The codebase keeps **simulation**, **rendering**, and **input** strictly separated.

```
src/
  core/        rng (mulberry32), Grid<T>, vector/tile helpers
  wfc/         tiles + adjacency rules, the WFC solver, map generation + playability pass
  sim/         the headless game model and rules (no DOM, fully unit-testable):
                 stats, entity, gamemap, world, astar, pathing, movement,
                 behaviors, ai, combat, fog, spatial, simulation, setup, config, orders
  render/      camera, HUD layout, canvas renderer, minimap (DOM/Canvas only)
  ui/          canvas HUD (resource bar, selection panel, command buttons) + DOM menus
  input/       DOM event binding → forwards to the session (no game logic)
  game/        GameSession (owns one match + the fixed-step loop), campaign, shared types
  main.ts      app shell: screen state machine + requestAnimationFrame loop
```

- **Simulation** is a pure function of state: `stepWorld(world, dt)` advances one fixed
  tick and mutates only the `World`. It has no knowledge of pixels, the camera, or input.
- **Fixed timestep, decoupled from rendering.** The simulation runs at a fixed 30 Hz
  (`SIM_HZ`); `GameSession` accumulates real frame time (scaled by the 1×/2× speed) and
  runs whole sim steps, while `requestAnimationFrame` renders every frame. This keeps the
  game deterministic and frame-rate-independent. (Measured cost: ~0.5 ms per step with
  130+ units on a 64×64 map — comfortably inside the 60 FPS budget.)
- **Spatial partitioning.** A uniform-grid spatial hash (`sim/spatial.ts`) backs target
  acquisition and unit separation so 100+ units stay cheap.
- **Pathfinding.** A\* on the tile grid (`sim/astar.ts`): 8-directional, octile
  heuristic, **no corner-cutting** through blocked diagonals, with an expansion budget.
- **Wave Function Collapse.** `wfc/wfc.ts` is a real tiled WFC solver — bitmask
  superpositions, minimal-entropy cell selection, and adjacency-constraint propagation to
  a fixpoint, with weighted collapse. `wfc/mapgen.ts` wraps it with a deterministic
  playability pass (see below).

## Wave Function Collapse & map generation

The tile set is grass, dirt, forest, water, rock/mountain and gold mine, each with a
weight and an explicit, symmetric adjacency table (`wfc/tiles.ts`): water borders only
water and dirt, forests sit among grass/dirt, mountains cluster, and gold mines only
touch grass/dirt clearings. The solver collapses the lowest-entropy cell, propagates
constraints, and retries deterministically (with a forked PRNG) on the rare contradiction.

After collapse, a **playability pass** runs entirely off the same seed:

1. Find the largest connected land component; pick two well-separated start tiles inside
   it (so they are mutually reachable by land).
2. Carve a small buildable clearing at each start.
3. Guarantee resources within reach of each start — plant forest / place a gold mine if
   the natural map fell short — and top up the poorer side for approximate fairness.
4. As a last resort (if a seed never yields a large enough, separated component) it falls
   back to fixed corner starts and carves a connecting land corridor, so a playable map
   is *always* produced for any seed.

## Campaign

Five levels of increasing size and difficulty (`game/campaign.ts`): Greenfields (32², AI
1) → Riverbend (48², AI 2) → Stonewatch (64², AI 3) → The Narrows (80², AI 4) → Ironhold
(96², AI 5). Larger maps trend toward more water/mountains and tighter chokepoints. The
level-select screen shows locked/unlocked state; completing a level unlocks the next.

## AI opponent

The scripted opponent (`sim/ai.ts`) maintains Worker saturation across gold and wood,
follows a supply-aware build order (Farm when supply is tight → Barracks → Lumber Mill →
more Farms / Guard Towers), continuously trains a mixed army, re-dispatches builders to
stalled construction sites, pulls its army home to defend when its base is threatened, and
launches escalating attack waves (first wave roughly four minutes in at difficulty 1,
sooner and larger at higher difficulty). Difficulty (1–5) scales the AI's starting
resources, harvest-rate bonus, and wave size/cadence.

## Tests

`npm run test` runs the suite (vitest, 27 tests):

- **WFC** (`tests/wfc.test.ts`): adjacency-table symmetry and constraints, full collapse
  with every output pair satisfying adjacency, determinism for a fixed seed, and the
  map-generation playability guarantees (two separated starts, gold + forest in reach,
  determinism).
- **A\*** (`tests/astar.test.ts`): shortest diagonal path length, no corner-cutting,
  unreachable → `null`, already-there → `[]`, and stop-adjacent mode.
- **Combat & supply** (`tests/combat.test.ts`): damage = max(1, dmg − armor), death/corpse
  handling, ranged projectile spawn + armor-adjusted impact damage, supply cap/usage
  accounting, training cost deduction + supply reservation, and prerequisite enforcement.
- **Simulation** (`tests/sim.test.ts`): full game setup, a multi-minute run that grows the
  economy without error, and determinism (identical seeds → identical state).
- **Rendering smoke** (`tests/render.test.ts`): the renderer, minimap, HUD and the whole
  `GameSession` update/render/input loop execute against a realistic world without
  throwing (a canvas/document stub stands in for the browser).

## Notable design decisions

- **No render interpolation.** Entities are drawn at their 30 Hz simulation positions;
  movement is smooth enough at that rate and it keeps the renderer a pure read of state.
- **Costs are charged on placement / enqueue** (Warcraft-style); cancelling a queued unit
  refunds it. Repair charges resources proportionally to HP restored.
- **Finite resources.** Each gold-mine tile holds 20 000 gold; each forest tile holds 120
  wood and turns to dirt (passable) when exhausted.
- **Starting Workers auto-harvest** (split between gold and wood) so a new base is
  immediately productive; Workers can also build a second Town Hall to expand.
- **Default seed** uses `Math.random()` *only* to pick the campaign seed when none is
  given; it is then displayed and fully reproducible via `?seed=`. All in-game randomness
  uses the seeded PRNG exclusively.
- **HUD on canvas, menus in DOM.** The in-match HUD (resource bar, minimap, selection
  panel, command buttons) is drawn on the canvas with hit-tested buttons; the
  menu/level-select/result screens are lightweight DOM overlays for easy text input.
