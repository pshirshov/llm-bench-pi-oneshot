# Warband

A complete, playable in-browser real-time strategy game in the spirit of Warcraft 2.
Maps are generated by a genuine Wave Function Collapse algorithm; everything else
(AI, pathfinding, combat, fog, UI) is implemented from scratch with no
runtime dependencies.

## Quick start

```sh
npm install        # one-time
npm run dev        # http://localhost:5173
npm run build      # tsc + vite production build
npm run preview    # serve the production build
npm test           # vitest unit tests
npm run lint       # eslint
npm run check      # tsc + vitest + eslint (CI gate)
```

Open the URL, pick Humans or Orcs, pick a level, and play. The current random
seed is shown in the top HUD. Add `?seed=42` to the URL to reproduce any map
exactly; add `?seed=42&campaign=1234&unlocked=5` to deep-link a campaign run.

## Architecture

The codebase is split into three strictly separated layers:

1. **Simulation** (`src/sim.ts`, `src/ai.ts`, `src/mapgen.ts`, `src/wfc.ts`,
   `src/pathfind.ts`)
   - Pure TypeScript functions over a `World` value (`src/state.ts`).
   - No DOM, no `requestAnimationFrame`, no time-of-day — you can step the
     sim from a unit test or a node script.
   - Fixed-timestep 60 Hz tick; the main loop accumulates wall-clock dt
     and dispatches as many sim steps as fit.
   - Determinism: every random number flows through one seeded PRNG
     (`mulberry32` in `src/rng.ts`). The seed is displayed in the HUD and can
     be set via the URL.

2. **Rendering / input** (`src/render.ts`, `src/input.ts`, `src/hud.ts`,
   `src/camera.ts`, `src/main.ts`)
   - All DOM, Canvas 2D, mouse and keyboard handling.
   - Reads the `World` and `RenderState` after each sim tick; never mutates
     state directly — issues high-level commands back to the sim
     (`orderMove`, `tryQueueBuilding`, etc.).

3. **Bootstrapping** (`src/main.ts`)
   - Main menu, level select, faction pick, victory screen, seed deep-link.

### Module map

```
src/
  rng.ts        — mulberry32 PRNG + helpers (rngInt, rngPick, rngWeighted)
  math.ts       — chebyshev/octile, clamp, lerp, dist², grid helpers
  data.ts       — TileDef, FactionDef, UnitStats, BuildingStats, TILE/UNIT/BUILDING tables
  state.ts      — World, UnitEntity, BuildingEntity, ProjectileEntity, FactionState
  wfc.ts        — Wave Function Collapse (min-entropy + weighted propagation)
  mapgen.ts     — WFC post-pass: two start locations, gold/forest reachability, repair
  pathfind.ts   — 8-dir A* with corner-cut guard, octile heuristic, binary heap
  sim.ts        — world creation, placeUnit/placeBuilding, tick (movement, combat,
                  worker state machine, training, construction, projectiles, fog, win check),
                  orderMove/orderAttack/orderBuild/orderRepair, tryQueueBuilding/Train
  ai.ts         — scripted-strategy AI (worker saturation, build order, training, waves, defense)
  camera.ts     — viewport, world<->screen, clamping, edge scroll
  input.ts      — mouse / keyboard handlers, control groups, build placement
  render.ts     — Canvas 2D draw of tiles, units, buildings, projectiles, selection,
                  build placement preview, move markers, fog of war
  hud.ts        — DOM HUD: top resource bar, bottom selection/command panel, minimap
  main.ts       — game loop, main menu, level select, victory screen
  styles.css    — UI styling
```

### Determinism guarantees

- `generateWFC(seed)` is fully deterministic: same seed → same tile array.
- `mapForLevel(campaignSeed, level)` is fully deterministic: it derives a WFC
  seed from the pair, then places and repairs two start locations. The repair
  RNG is also derived.
- The sim step uses one PRNG whose initial seed is set from the URL; the
  `Math.random()` calls inside the AI are the only non-seeded randomness, and
  they only affect tie-breaking (e.g. which building a worker repairs first).
  Core gameplay (map, pathfinding, combat damage) is fully reproducible.

## Spec decisions

- **No external assets.** Every sprite is a colored shape drawn programmatically.
  See the `TILE_PALETTE` table in `src/render.ts` and the `drawBuilding` /
  `drawUnit` / `drawProjectile` functions.
- **No runtime dependencies.** `package.json` `dependencies` is empty; all
  tooling is in `devDependencies`.
- **Map post-processing.** The WFC alone doesn't produce large contiguous
  buildable regions (it's a *maximally-different-neighbors* algorithm), so
  `mapgen.ts` finds candidate 5×5 buildable regions, then explicitly clears
  the chosen start locations to grass. The AI can still walk on the natural
  forest/water/rock between starts.
- **A* corner cutting.** Diagonal moves are allowed only if both adjacent
  cardinal tiles are walkable; the same rule applies to the diagonal
  pass-through in the heuristic. Tested.
- **Vision / fog.** Fog of war is per-faction, per-tile. LOS is blocked by
  forest and rock; trees and rock are drawn on explored-but-not-visible tiles
  but enemy units/buildings are not. The minimap respects fog.
- **Damage.** `max(1, attacker_damage - defender_armor)`. Tested.
- **Unit armor** is 0 in the data table (we left room for it but kept melee
  at 2 and ranged/worker at 0 to keep combat readable). Buildings do have
  armor; towers have armor 8, town halls 20.
- **AI.** A scripted-strategy AI (`src/ai.ts`) — not a Monte Carlo / RL
  agent. It maintains worker saturation, follows a supply-ahead-of-demand
  build order, trains a mixed army, and sends escalating attack waves.
  Difficulty (1–5) scales starting resources, target population, wave size,
  and the gap between waves.
- **Control groups.** `Ctrl+digit` saves, `digit` alone recalls, double-tap
  to re-center. Both are wired in `src/input.ts`.
- **Pause / speed.** Space toggles pause; `1` is 1×, `2` is 2×. Both are
  HUD-readable.
- **Campaign.** Five levels, 32×32 → 96×96, difficulty 1 → 5. Progress is
  stored in `localStorage` (key `warband_unlocked`); a level unlocks when
  you win the previous one.

## Tests

`npm test` runs the Vitest suite. 49 tests covering:

- **PRNG** — determinism, range, seed sensitivity (3 assertions)
- **WFC** — determinism, adjacency rules, adjacency symmetry, gold-mine / water
  shoreline constraints, varied output across seeds (6)
- **A\*** — straight path, diagonal path, walls, unreachable, corner-cut guard,
  single-tile start (7)
- **Combat & supply** — armor math, ranged unit stats, heavy unit cost,
  building stats, supply cap (6)
- **Map generation** — two valid reachable starts, cleared ground, gold &
  forest reachability, size + difficulty scaling per level, determinism (5)
- **World & sim** — town hall + workers, fog, tick stability, supply cap,
  canTrain validation, build placement, AI builds barracks, AI produces
  military, combat damage, death cleanup, buildability, training without
  prerequisites, pathing, duplicate-build prevention (16)
- **Data tables** — unit / building positive-stat sanity (2)
- **Resource tiles** — gold/wood table, search (2)
